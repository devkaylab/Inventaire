# Quantinvo — notes pour l'agent

Ce fichier est chargé à chaque session : il reste COURT. L'historique détaillé
(pourquoi chaque décision, pièges payés, vérifications) vit dans `docs/notes/`,
une fiche par chantier. **Lire la fiche du sujet avant d'y toucher** (grep sur
`docs/notes/` pour un mot-clé). Ne jamais réécrire l'historique ici : ajouter
ou corriger une fiche, et une ligne dans l'index ci-dessous si elle est neuve.

## Règles qui valent partout

- **Expo a changé** : lire https://docs.expo.dev/versions/v56.0.0/ avant d'écrire du code natif.
- **Julien** : tutoyer, réponses courtes, pas d'emoji, langage simple. Commit + push à chaque changement terminé (push = déploie le site).
- **Builds** : iOS local = `./scripts/simulateur.sh` seul (jamais `xcodebuild` à la main) ; publication iOS = Xcode → Organizer, par Julien. Android = `./scripts/pixel.sh` (test) / `./scripts/play.sh` (publication). `android/` est généré et gitignoré, `ios/` est versionné. Le déclenchement d'un build appartient à Julien. ⚠️ `supportsTablet: false` n'empêche pas l'installation sur iPad et Apple y revoit l'app (refus du build 5, 22 septembre) : la lancer sur un simulateur iPad avant chaque dépôt — `CONSOLE=1 CONFIG=Release ./scripts/simulateur.sh ipad`. ⚠️⚠️ **iOS se compile avec Xcode 26.6, JAMAIS Xcode 27** : le SDK 27 impose UIScene, qu'Expo 56 ne sait pas faire, et l'app plante au lancement sur iOS 27. `./scripts/simulateur.sh` **impose Xcode 26.6 lui-même** depuis le 4 octobre 2026 et refuse un Xcode 27 (`DEVELOPER_DIR` passé à la main reste prioritaire) ; pour toute AUTRE commande, préfixer par `DEVELOPER_DIR=/Applications/Xcode-26.6.app/Contents/Developer` (pas de `xcode-select`, pas de mot de passe) ; Julien archive depuis **Xcode-26.6**. Xcode 26.6 ne pilote pas un simulateur iOS 27 : compiler en visant un appareil iOS 26.x, puis `simctl install` + `launch` sur l'appareil iOS 27. ⚠️⚠️ **AUCUN BUILD NE PART EN REVUE SANS AVOIR ÉTÉ OUVERT DEPUIS TESTFLIGHT**, une fois, sur un vrai appareil — juste l'ouvrir. Le défaut du build 5 n'existait QUE dans l'archive : simulateur et installation directe depuis Xcode passaient au vert. TestFlight sert l'artefact que l'examinateur lance, avec les autorisations de distribution (`get-task-allow`, APNs de production) ; rien d'autre ne le teste. ⚠️ **Testeur interne bloqué en « Aucun build disponible »**, aucun e-mail, TestFlight n'affichant que « Redeem » : remplir **« Éléments à tester »** sur le build (TestFlight → le build → Détails des tests). L'invitation part aussitôt. Semble n'être nécessaire qu'à la PREMIÈRE distribution — les builds suivants partent avec le champ vide. Ne pas chercher du côté de l'Apple ID, une heure y a été perdue.
- ⚠️ **MIGRATION APPLE — FAITE le 7 octobre 2026, et c'était une CONVERSION du compte.** L'adhésion personnelle continue jusqu'en **avril 2027**, sans rachat : même équipe, nouveau nom et nouveau type. Donc **ni App Transfer, ni nouveau bundle ID, ni nouvel examen** — l'app garde sa fiche, ses avis et son historique. (Identifiant d'inscription `9L95Q9R29F` ; dossier support 102964327628.) ⚠️ **IL RESTE TROIS VÉRIFICATIONS, et la première conditionne la suite** : (1) le portail **Certificates, Identifiers & Profiles** répond-il ? Il était fermé « pendant la migration » — **tant que ce n'est pas constaté, on garde les consignes : pas de capability ajoutée, pas de changement de bundle ID, pas d'appareil enregistré** ; (2) ⚠️ le **nom du vendeur** change quand l'accord est traité, et Apple attend des informations : App Store Connect → **Business** (ex-« Contrats, taxes et opérations bancaires »), y compléter TOUTES les tâches ouvertes de l'entité légale. Ni délai ni défaut, et rien à relancer — le courriel du 7 octobre au soir le dit. ⚠️ Ces tâches (identifiant fiscal, formulaires, banque) n'appartiennent qu'à Julien. ⚠️ Et Quantinvo ne vend RIEN par l'App Store : si Business réclame un accord « Paid Apps » ou un compte bancaire, le demander sur le dossier 102964327628 plutôt que d'inventer ; (3) au prochain build, que Xcode résout toujours le profil — l'équipe garde son identifiant mais change de nom, et ça se voit à l'archivage, pas à la lecture. Retirer cette ligne quand les trois sont faites. Détail : `docs/entreprise/reponse-apple-migration-organisation.md`.
- **Numéros de build** : iOS vit à 3 endroits (app.json, Info.plist, project.pbxproj ×2), monté juste avant l'archive ; Android `versionCode` dans app.json, augmente à chaque dépôt. Lire l'état réel avant d'affirmer.
- **Dépendance native** → `cd ios && LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install`, et LIRE sa sortie.
- **Migrations** : appliquer par `supabase db query --file … --linked` ou la console, JAMAIS `db push`. ⚠️ **Depuis le 30 octobre 2026, une table neuve porte ses droits** : Supabase n'accorde plus l'accès de l'API automatiquement, et une table créée sans `grant` est injoignable depuis l'app (« permission denied »). Mettre `grant select, insert, update, delete on public.<table> to authenticated;` et `to service_role;` dans la migration qui la crée — ou un `revoke … from authenticated` si elle doit rester hors API. `grant` ouvre la porte, RLS trie les lignes : les deux, toujours. Les tables d'avant gardent leurs droits acquis, on n'y touche pas. Contrôle de dérive : `node scripts/mesurer-migrations.mjs`. `create or replace` rend EXECUTE à PUBLIC : reposer les droits (`revoke … from public, anon`) dans la même migration. Changer une signature = `drop` de l'ancienne.
- **Sécurité** : analyser la BASE réelle (`pg_get_functiondef`, `pg_policies`), pas le dossier. Garde sur la ligne visée, jamais sur un paramètre de l'appelant. Fonctions sœurs : les comparer ligne à ligne.
- **Fonctions edge** : le dépôt ne déploie rien. Déployer par le CLI ; relever `verify_jwt` sur la base AVANT, les publiques se déploient avec `--no-verify-jwt`. Vérifier après (download + diff). Le site se déploie avant les fonctions edge.
- **Stripe** : les Price ne sont jamais créés par le code (sauf devis mensuel négocié). Live seulement APRÈS publication sur les deux boutiques (décision de Julien). La clé live devra avoir les permissions Subscriptions.
- ⚠️ **Les liens d'e-mail vivent 24 h, et l'alerte de Supabase est ASSUMÉE.** Un seul réglage (`Authentication → Providers → Email → Email OTP Expiration`) gouverne le lien qui CRÉE un mot de passe et celui qui le RÉINITIALISE ; 24 h est le maximum autorisé, choisi le 6 octobre 2026 parce qu'une heure tuait l'invitation d'un compteur qui ouvre son courrier le lendemain. L'analyseur lève `auth_otp_long_expiry` au-delà d'une heure : **ne pas repasser à une heure pour éteindre le voyant** — il vise le code à six chiffres de Supabase, que ce produit ne vérifie jamais (`verifyOtp` ne reçoit qu'un `token_hash`, à un seul endroit ; le code à six chiffres de l'inscription est le nôtre, 10 minutes). La durée est recopiée dans `DUREE_LIEN_HEURES` (`_shared/email.ts`) parce que les e-mails l'annoncent : changer l'un sans l'autre écrit un mensonge. Fiche `docs/notes/121`.
- ⚠️ **Vente fermée par `STRIPE_LIVE_PRET`, plus par les mentions légales** (7 octobre 2026). `venteOuverte() = mentionsCompletes() && STRIPE_LIVE_PRET` : **deux** conditions, et le `&&` échoue du bon côté — oublier un drapeau garde la vente FERMÉE. Les mentions sont complètes depuis le 7 octobre (adresse et téléphone de Vercel), donc la page est publiée, indexable et dans le plan du site. Elles étaient retenues exprès depuis le 15 septembre parce qu'une seule fonction portait un devoir légal ET une décision commerciale : un devoir légal inaccompli pour empêcher une vente. `STRIPE_LIVE_PRET` se lève quand le compte est en LIVE avec les huit Price et la permission Subscriptions ; drapeaux jumeaux `VENTE_OUVERTE` dans `inscription` et `subscribe-online`. **Un drapeau par boutique** dans `web/lib/appStores.ts` : `PUBLIEE_IOS` (vrai depuis le 27 septembre 2026) et `PUBLIEE_ANDROID` (Play examine encore). Il n'existe plus de `PUBLIEE` seul — il aurait ouvert les deux fiches d'un coup. Vérifier que la fiche répond AVANT de lever un drapeau.
- ⚠️⚠️ **`main` NE PORTE JAMAIS LE CHANTIER ON-DEMAND, et un hook le refuse** (9 octobre 2026). Le report se fait TOUJOURS `main` → `on-demand` (`git checkout on-demand && git merge main`), **jamais l'inverse** : ce jour-là la commande a été écrite dans le mauvais sens, la fusion a réussi en silence, et `main` a porté les 31 migrations et tout le site d'On-Demand. Rien n'a été poussé par chance, pas par construction — un `push` de plus déployait sur `www.quantinvo.com` un projet dont la règle dit qu'il n'est pas publiable. `scripts/git-hooks/pre-push` cherche la SIGNATURE du chantier (la migration qui crée la table `missions`), pas une liste de noms. **À installer dans tout clone** : `git config core.hooksPath scripts/git-hooks` — `core.hooksPath` n'est pas versionné. Le jour où la fusion est voulue : `git push --no-verify`, après l'ordre du jour J de `docs/notes/109`.
- **Gardes** : `web/tests/` et `tests/`. Une garde déduit sa liste, ne la cite pas ; lit le code sans ses commentaires ; passe par `derniereDefinition()` (jamais un nom de migration en dur). Saboter pour vérifier qu'elle mord. Ne jamais filtrer la sortie d'un contrôle qui garde un `&&`.
- **Lint du site** : `npm run lint` depuis `web/` (`eslint .`).
- **Identité** : Ardoise (outil) et Registre (ce qui fait foi : rapport, écarts, devis). Pas de design « IA ». Tokens partagés : `src/constants/ink.ts` ↔ `web/app/globals.css`.
- **Decks et documents** : ⚠️ **AUCUN deck ne se régénère, et aucun fichier de son dossier ne s'écrase, sans que Julien le demande** — il les retouche à la main, et une génération efface ses modifications sans trace (28 septembre 2026). Modifier un script, lire un deck : oui. Lancer `node build-*.js` : seulement sur demande. Atelier et pièges : `docs/entreprise/deck/LISEZMOI.md`.
- **Doublons volontaires** app/site qui bougent ensemble : presence, import, report, password, baliseSeries, erreursServeur, grille tarifaire (5 copies, un test compare).
- **i18n** : la phrase française est la clé (`t('…')`) ; ajouter l'entrée anglaise dans `src/i18n/en.ts` / `web/i18n/en.ts`.
- **Vérifier l'effet, pas le code de retour** ; une page à deux états se regarde dans les deux ; un chiffre invraisemblable est d'abord un défaut de mesure ; une note d'état se vérifie avant d'être citée.
- **Ne jamais réintroduire** : le tutoriel intégré, la redirection auto vers l'unique inventaire, `Modal` pour `GeneratingOverlay`, un `max-width` sur `.app-main`.
