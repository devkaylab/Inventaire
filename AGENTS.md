# Quantinvo — notes pour l'agent

Ce fichier est chargé à chaque session : il reste COURT. L'historique détaillé
(pourquoi chaque décision, pièges payés, vérifications) vit dans `docs/notes/`,
une fiche par chantier. **Lire la fiche du sujet avant d'y toucher** (grep sur
`docs/notes/` pour un mot-clé). Ne jamais réécrire l'historique ici : ajouter
ou corriger une fiche, et une ligne dans l'index ci-dessous si elle est neuve.

## Règles qui valent partout

- **Expo a changé** : lire https://docs.expo.dev/versions/v56.0.0/ avant d'écrire du code natif.
- **Julien** : tutoyer, réponses courtes, pas d'emoji, langage simple. Commit + push à chaque changement terminé (push = déploie le site).
- **Builds** : iOS local = `./scripts/simulateur.sh` seul (jamais `xcodebuild` à la main) ; publication iOS = Xcode → Organizer, par Julien. Android = `./scripts/pixel.sh` (test) / `./scripts/play.sh` (publication). `android/` est généré et gitignoré, `ios/` est versionné. Le déclenchement d'un build appartient à Julien.
- **Numéros de build** : iOS vit à 3 endroits (app.json, Info.plist, project.pbxproj ×2), monté juste avant l'archive ; Android `versionCode` dans app.json, augmente à chaque dépôt. Lire l'état réel avant d'affirmer.
- **Dépendance native** → `cd ios && LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install`, et LIRE sa sortie.
- **Migrations** : appliquer par `supabase db query --file … --linked` ou la console, JAMAIS `db push`. Contrôle de dérive : `node scripts/mesurer-migrations.mjs`. **Avant d'appliquer** : `./.venv-pg/bin/python scripts/verifier-migrations.py` (la syntaxe, corps PL/pgSQL compris) puis `./scripts/replique/verifier.sh` (ce qu'elle CHANGE, rejoué sous RLS) — une migration qui compile et dont chaque policy a été relue peut casser un parcours. `create or replace` rend EXECUTE à PUBLIC : reposer les droits (`revoke … from public, anon`) dans la même migration. Changer une signature = `drop` de l'ancienne.
- **On-Demand ne touche pas à Quantinvo OS** (règle de Julien, 20 septembre 2026, l'app étant en publication) : ses migrations AJOUTENT des policies à côté de celles d'OS — les permissives se combinent en `OU` — et n'en réécrivent aucune. Une seule fait exception, `20260920200001`, qui le dit dans son nom. Gardes : `web/tests/on-demand-separation.test.ts` et le retrait complet dans `scripts/replique/`.
- **Sécurité** : analyser la BASE réelle (`pg_get_functiondef`, `pg_policies`), pas le dossier. Garde sur la ligne visée, jamais sur un paramètre de l'appelant. Fonctions sœurs : les comparer ligne à ligne.
- **Fonctions edge** : le dépôt ne déploie rien. Déployer par le CLI ; relever `verify_jwt` sur la base AVANT, les publiques se déploient avec `--no-verify-jwt`. Vérifier après (download + diff). Le site se déploie avant les fonctions edge.
- **Stripe** : les Price ne sont jamais créés par le code (sauf devis mensuel négocié). Live seulement APRÈS publication sur les deux boutiques (décision de Julien). La clé live devra avoir les permissions Subscriptions.
- **Vente fermée** tant que `web/lib/legal.ts` est incomplet (`venteOuverte()` = `mentionsCompletes()`) ; drapeaux jumeaux `VENTE_OUVERTE` dans `inscription` et `subscribe-online`. `PUBLIEE` dans `web/lib/appStores.ts` passe à true le jour de la publication.
- **Gardes** : `web/tests/` et `tests/`. Une garde déduit sa liste, ne la cite pas ; lit le code sans ses commentaires ; passe par `derniereDefinition()` (jamais un nom de migration en dur). Saboter pour vérifier qu'elle mord. Ne jamais filtrer la sortie d'un contrôle qui garde un `&&`.
- **Lint du site** : `npm run lint` depuis `web/` (`eslint .`).
- **Identité** : Ardoise (outil) et Registre (ce qui fait foi : rapport, écarts, devis). Pas de design « IA ». Tokens partagés : `src/constants/ink.ts` ↔ `web/app/globals.css`.
- **Doublons volontaires** app/site qui bougent ensemble : presence, import, report, password, baliseSeries, erreursServeur, grille tarifaire (5 copies, un test compare).
- **i18n** : la phrase française est la clé (`t('…')`) ; ajouter l'entrée anglaise dans `src/i18n/en.ts` / `web/i18n/en.ts`.
- **Vérifier l'effet, pas le code de retour** ; une page à deux états se regarde dans les deux ; un chiffre invraisemblable est d'abord un défaut de mesure ; une note d'état se vérifie avant d'être citée.
- **Ne jamais réintroduire** : le tutoriel intégré, la redirection auto vers l'unique inventaire, `Modal` pour `GeneratingOverlay`, un `max-width` sur `.app-main`.
