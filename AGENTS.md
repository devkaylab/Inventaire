- **Dépendance native** → `cd ios && LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install`, et LIRE sa sortie. ⚠️⚠️ **Et LIRE sa sortie NE SUFFIT PAS : `pod install` sort à 0 en laissant le `Podfile.lock` PÉRIMÉ.** Le 9 octobre 2026, après un `expo install --fix`, il n'a mis à jour aucune version déjà verrouillée et n'a prévenu que pour **un** pod sur dix-neuf — `Expo` lui-même restait à 56.0.11 dans le lock quand 56.0.23 était installé. La compilation iOS serait partie sur l'ancien code natif, sans rien dire. **Ce qui le voit, c'est de comparer le lock à `node_modules`**, pas le code de retour ; correctif `pod update <pods> --no-repo-update`. ⚠️ En zsh, `pod update $PODS` passe toute la liste comme UN nom de pod (zsh ne découpe pas une variable non quotée) et CocoaPods sort encore à 0 : écrire `${=PODS}`, et vérifier dans le lock. ⚠️ `Yoga` et `hermes-engine` sont de faux positifs d'une telle comparaison, leurs podspecs portent une version de convention.
- ⚠️ **Le chemin du projet ne contient pas d'espace, et une garde le tient** (9 octobre 2026) : le dossier s'appelait « App inventaire », et les script phases générées en `bash -l -c "<chemin>"` coupaient au premier blanc — il fallait un `post_install` écrit à la main dans `ios/Podfile`, que tout prebuild effaçait. Le dossier est `appinventaire`, le crochet est **retiré**, et `tests/chemin-du-projet.test.ts` refuse un chemin à espace en lisant le chemin RÉEL. Sans le crochet, un chemin à espace ne rate plus visiblement : il rate sur une compilation iOS dont l'erreur désigne un dossier tronqué. **Ne pas remettre le crochet — déplacer le projet.** Fiche `docs/notes/106`.
- **Migrations** : appliquer par `supabase db query --file … --linked` ou la console, JAMAIS `db push`. ⚠️ **Depuis le 30 octobre 2026, une table neuve porte ses droits** : Supabase n'accorde plus l'accès de l'API automatiquement, et une table créée sans `grant` est injoignable depuis l'app (« permission denied »). Mettre `grant select, insert, update, delete on public.<table> to authenticated;` et `to service_role;` dans la migration qui la crée — ou un `revoke … from authenticated` si elle doit rester hors API. `grant` ouvre la porte, RLS trie les lignes : les deux, toujours. ⚠️ **Et un `grant select` SANS liste de colonnes porte sur toutes les colonnes, et supersède un grant nominatif** : une table dont le client ne doit voir qu'une partie se donne colonne par colonne, et un `grant` large posé plus tard pour réparer un « permission denied » rouvre tout en silence (5 octobre 2026, `missions` : coût et marge lisibles par le client pendant un jour). ⚠️ **Et un `grant select (colonnes)` S'AJOUTE à ceux déjà posés** — seul un `revoke` retire. Une garde sur les droits rejoue les grant/revoke dans l'ordre des fichiers **en CUMULANT** : la garde modélisait un remplacement, et le 7 octobre 2026 une seconde migration de colonnes l'a fait croire que le client ne lisait plus que 4 colonnes sur 48 — elle serait tombée du bon côté par hasard. Le droit effectif se lit dans `information_schema.column_privileges`, jamais dans le dernier `grant` écrit. Garde : `web/tests/prix-on-demand.test.ts`. Contrôle de dérive : `node scripts/mesurer-migrations.mjs`. **Avant d'appliquer** : `./.venv-pg/bin/python scripts/verifier-migrations.py` (la syntaxe, corps PL/pgSQL compris) puis `./scripts/replique/verifier.sh` (ce qu'elle CHANGE, rejoué sous RLS) — une migration qui compile et dont chaque policy a été relue peut casser un parcours. `create or replace` rend EXECUTE à PUBLIC : reposer les droits (`revoke … from public, anon`) dans la même migration. Changer une signature = `drop` de l'ancienne. **Toute fonction fixe son `search_path`** (garde : `web/tests/search-path.test.ts`) — trois l'avaient oublié le 20 septembre 2026, et seul le contrôle de sécurité de Supabase, APRÈS application, l'a vu. **Après avoir appliqué : `get_advisors(type: security)`.**
- **On-Demand ne touche pas à Quantinvo OS** (règle de Julien, 20 septembre 2026, l'app étant en publication) : ses migrations AJOUTENT des policies à côté de celles d'OS — les permissives se combinent en `OU` — et n'en réécrivent aucune. Une seule fait exception, `20260920200001`, qui le dit dans son nom. Gardes : `web/tests/on-demand-separation.test.ts` et le retrait complet dans `scripts/replique/`.
- **Sécurité** : analyser la BASE réelle (`pg_get_functiondef`, `pg_policies`), pas le dossier. Garde sur la ligne visée, jamais sur un paramètre de l'appelant. Fonctions sœurs : les comparer ligne à ligne.
- **Fonctions edge** : le dépôt ne déploie rien. Déployer par le CLI ; relever `verify_jwt` sur la base AVANT, les publiques se déploient avec `--no-verify-jwt`. Vérifier après (download + diff). Le site se déploie avant les fonctions edge.
- **Stripe** : les Price ne sont jamais créés par le code (sauf devis mensuel négocié). Live seulement APRÈS publication sur les deux boutiques (décision de Julien). La clé live devra avoir les permissions Subscriptions.
- ⚠️ **Les liens d'e-mail vivent 24 h, et l'alerte de Supabase est ASSUMÉE.** Un seul réglage (`Authentication → Providers → Email → Email OTP Expiration`) gouverne le lien qui CRÉE un mot de passe et celui qui le RÉINITIALISE ; 24 h est le maximum autorisé, choisi le 6 octobre 2026 parce qu'une heure tuait l'invitation d'un compteur qui ouvre son courrier le lendemain. L'analyseur lève `auth_otp_long_expiry` au-delà d'une heure : **ne pas repasser à une heure pour éteindre le voyant** — il vise le code à six chiffres de Supabase, que ce produit ne vérifie jamais (`verifyOtp` ne reçoit qu'un `token_hash`, à un seul endroit ; le code à six chiffres de l'inscription est le nôtre, 10 minutes). La durée est recopiée dans `DUREE_LIEN_HEURES` (`_shared/email.ts`) parce que les e-mails l'annoncent : changer l'un sans l'autre écrit un mensonge. Fiche `docs/notes/121`.
- ⚠️ **Une location se paie en deux temps, et l'ordre est tout** (7 octobre 2026) : l'empreinte de la carte AVANT — c'est elle, et rien d'autre, qui ouvre la fenêtre d'accès — puis le prélèvement au septième jour, par une facture Stripe. `missions` a une **machine d'états** (`transition_mission_permise`) qui refuse les raccourcis : jouer la transition avant d'écrire un `set etat`, un `update` qui saute un pas lève `check_violation` chez le premier client. La clé d'idempotence d'un RÈGLEMENT doit varier à chaque tentative (Stripe mémorise aussi les refus) ; celles de la facture, non. **Rien n'est déployé ni éprouvé contre Stripe** — il n'existe pas de clé hors du projet. Fiche `docs/notes/122`.
- ⚠️ **Vente fermée par `STRIPE_LIVE_PRET`, plus par les mentions légales** (7 octobre 2026). `venteOuverte() = mentionsCompletes() && STRIPE_LIVE_PRET` : **deux** conditions, et le `&&` échoue du bon côté — oublier un drapeau garde la vente FERMÉE. Les mentions sont complètes depuis le 7 octobre (adresse et téléphone de Vercel), donc la page est publiée, indexable et dans le plan du site. Elles étaient retenues exprès depuis le 15 septembre parce qu'une seule fonction portait un devoir légal ET une décision commerciale : un devoir légal inaccompli pour empêcher une vente. `STRIPE_LIVE_PRET` se lève quand le compte est en LIVE avec les huit Price et la permission Subscriptions ; drapeaux jumeaux `VENTE_OUVERTE` dans `inscription` et `subscribe-online`. **Un drapeau par boutique** dans `web/lib/appStores.ts` : `PUBLIEE_IOS` (vrai depuis le 27 septembre 2026) et `PUBLIEE_ANDROID` (Play examine encore). Il n'existe plus de `PUBLIEE` seul — il aurait ouvert les deux fiches d'un coup. Vérifier que la fiche répond AVANT de lever un drapeau.
- ⚠️⚠️ **`main` NE PORTE JAMAIS LE CHANTIER ON-DEMAND, et un hook le refuse** (9 octobre 2026). Le report se fait TOUJOURS `main` → `on-demand` (`git checkout on-demand && git merge main`), **jamais l'inverse** : ce jour-là la commande a été écrite dans le mauvais sens, la fusion a réussi en silence, et `main` a porté les 31 migrations et tout le site d'On-Demand. Rien n'a été poussé par chance, pas par construction — un `push` de plus déployait sur `www.quantinvo.com` un projet dont la règle dit qu'il n'est pas publiable. `scripts/git-hooks/pre-push` cherche la SIGNATURE du chantier (la migration qui crée la table `missions`), pas une liste de noms. **À installer dans tout clone** : `git config core.hooksPath scripts/git-hooks` — `core.hooksPath` n'est pas versionné. Le jour où la fusion est voulue : `git push --no-verify`, après l'ordre du jour J de `docs/notes/109`.
- ⚠️ **Le rôle sur un inventaire SE CALCULE** (9 octobre 2026) : `role_de_session` en base, un déclencheur `before insert or update` sur `session_members` l'impose, et `ca_set_user_role` fait suivre les inventaires. **Aucun écran, aucune passerelle, aucune fonction edge n'envoie de rôle** — les écrans affichent un constat lu dans l'annuaire, et la fonction edge relit celui que la base a posé. La leçon : « en base c'est bon » se VÉRIFIE — ici la fonction edge lisait le rôle dans le corps de la requête et l'écrivait avec la clé de service, hors RLS. ⚠️ `role_de_session` ne se supprime jamais au retrait : `ca_set_user_role` (une fonction d'OS) l'appelle. Fiche `docs/notes/123`.
- ⚠️ **Tout appel réseau a un budget** (9 octobre 2026, `src/lib/reseau.ts`) : **2,5 s** sur les trois appels qu'un compteur attend (résoudre un code, enregistrer un comptage, ouvrir/clôturer une balise), **20 s** en filet dans le client — et le filet s'efface devant le signal de l'appelant. En zone grise une requête ne tombe pas, elle PEND : sans budget, l'app attendait le délai d'iOS. ⚠️⚠️ **Une annulation doit rester comprise comme une panne réseau** (`isNetworkError`), sinon le budget coupe la requête et l'écran affiche une erreur au lieu de basculer hors ligne — l'app serait plus cassante qu'avant. ⚠️ **On annule (`abortSignal`), on ne course pas un minuteur** : une écriture abandonnée mais en vol arriverait après la mise en file et ferait deux lignes pour un scan. Et **le scan lit le cache AVANT le réseau** — zéro appel pour un code du référentiel, mesuré. ⚠️ Ce qu'on n'a PAS fait : mettre le comptage en file systématiquement — une règle d'`offlineSync.ts` veut qu'un refus du serveur reste visible immédiatement. Fiche `docs/notes/124`.
- **Gardes** : `web/tests/` et `tests/`. Une garde déduit sa liste, ne la cite pas ; lit le code sans ses commentaires ; passe par `derniereDefinition()` (jamais un nom de migration en dur). Saboter pour vérifier qu'elle mord. Ne jamais filtrer la sortie d'un contrôle qui garde un `&&`.
- **Lint du site** : `npm run lint` depuis `web/` (`eslint .`).
- **Identité** : Ardoise (outil) et Registre (ce qui fait foi : rapport, écarts, devis). Pas de design « IA ». Tokens partagés : `src/constants/ink.ts` ↔ `web/app/globals.css`.

Les messageries proxient et mettent en cache PAR URL : remplacer le fichier sous la même adresse ne change rien pour qui a déjà reçu un message. Changer une image = redéployer les 16 fonctions qui envoient du courrier (la constante est bundlée).
- **Decks et documents** : ⚠️ **AUCUN deck ne se régénère, et aucun fichier de son dossier ne s'écrase, sans que Julien le demande** — il les retouche à la main, et une génération efface ses modifications sans trace (28 septembre 2026). Modifier un script, lire un deck : oui. Lancer `node build-*.js` : seulement sur demande. Atelier et pièges : `docs/entreprise/deck/LISEZMOI.md`.
